# 分阶段测试路线

测试按阶段推进；每个阶段都可以长期运行、暂停和恢复，不要求一次完成。后一阶段不应
覆盖前一阶段的失败证据，也不应因为测试通过自动打开 Live。

## 总原则

- 默认始终是 `PAPER + LIVE_DISABLED + liveAllowed=false`；
- 每阶段保存原始报告、版本、时间和哈希；
- 失败时保留证据并回到安全状态，不手工改数据库“通过”；
- 真实钱包、真实授权和真实资金只在明确的生产验收阶段出现；
- 任何阶段都不加载私钥/助记词到仓库或 Node 配置。

## 阶段 1：启动、关闭和重启

目标：证明本地入口可以安全启动、心跳推进、退出、关机后再次恢复。

建议步骤：

```bash
zsh -n scripts/launch-hecatonchires-ui.command
pnpm operator:ui
```

验收：

- 页面能打开，`generatedAt` 持续变化；
- 启动后是 `PAPER + LIVE_DISABLED`；
- 点击“退出”后端口关闭；
- 重启不会自动恢复 Live、连接钱包或下单；
- 数据库完整性检查通过。

## 阶段 2：Paper 长时间运行

目标：验证模拟账户、规则集、Reservation、Position、PnL、恢复和账本一致性。

验收：

- 使用专用 Paper 账户；
- 按计划完成连续运行和累计运行时长；
- 没有未恢复 checkpoint、账本不一致或未知状态；
- 运行期间不产生真实订单或链上写入。

Paper 长测可以因电脑关机而暂停；恢复后应按 checkpoint 继续核对，不把停机时间伪造
为成交。

## 阶段 3：Observe 数据同步

目标：验证 Polygon 已确认事件、Trades/Activity、Positions、pUSD 和重组/断线恢复。

验收：

- 目标地址绑定正确；
- 无未恢复连接 gap、`MAJOR_DESYNC` 或 cursor hash 不一致；
- 最终状态为 `SYNCED`；
- 原始 Capture、分页和对账证据可追溯；
- Observe 只读，不进入 Live 执行。

## 阶段 4：钱包只读身份验证

目标：只证明当前浏览器钱包控制公开地址和正确网络。

验收：

- EIP-1193 provider 身份明确；
- Polygon chain id 正确；
- `personal_sign` challenge 新鲜且绑定当前会话；
- session lease、账户切换和断开行为正确；
- 不产生 approve、订单或其他链上写入。

连接钱包不代表订单授权，也不代表余额、allowance 或 CLOB 已通过。

## 阶段 5：余额、allowance、仓位和 CLOB 认证

目标：用真实 provider 做只读生产前置检查。

验收：

- 钱包余额、allowance、外部订单、成交和仓位读取一致；
- CLOB 认证只在当前钱包会话内惰性建立；
- 空余额不被当作“连接失败”，但具体订单仍需逐笔资金检查；
- 地域、合规和时钟证据新鲜；
- 任一读取失败都保留原因并 fail closed。

此阶段仍不发送真实订单。

## 阶段 6：Live Gate 和失败回滚

目标：验证 arming、最终确认、启动恢复、后台异常和紧急停用。

验收：

- 只能按 Gate 顺序进入 `LIVE_ARMING`/`LIVE_ACTIVE`；
- 任一前置条件失败都回到 `PAPER + LIVE_DISABLED`；
- 旧 session、旧源码或旧 validation artifact 会被拒绝；
- 服务退出、钱包断开和后台异常都会安全停用；
- 没有交易动作作为验证副作用。

通过本阶段不等于用户已授权真实交易。

## 阶段 7：极小金额受限 canary

目标：在单独、明确授权的隔离钱包中验证极小金额的一次受限外部动作。

前置：

- 阶段 1—6 全部有新鲜通过证据；
- 用户在当次会话明确授权；
- 限额、地域、合规、余额、allowance、市场和对账均已记录；
- 外部审计或内部审批允许进行 canary。

验收：

- 只执行预先批准的单笔范围；
- 钱包弹窗逐笔确认；
- 记录 submit、pending、fill/cancel、费用和链上回执；
- 失败立即停止，不自动扩大限额。

## 阶段 8：成交、取消、对账、恢复和紧急关闭

目标：证明完整外部生命周期，而不是只证明“请求被接受”。

验收：

- 真实成交与本地订单/账本一致；
- 取消、部分成交、超时和重复回调幂等；
- 外部余额、仓位、订单和本地 ledger 对账一致；
- 重启/崩溃恢复不重复下单；
- 紧急关闭可用且有审计证据；
- 结果由人工审阅后再决定是否扩大运行范围。
